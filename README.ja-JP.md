F-Droid は GitHub でクライアント APK を公開するのをやめました。このリポジトリは、その入口を残すためのものです。

私は中国の中学生です。正直に言うと、技術的なスキルはまだ限られています。F-Droid のコードを修正したり、機能を追加したりすることはできません。自由ソフトウェアの世界には、今の私には理解しきれないことがたくさんあります。それでも、オープンソースが大切にしている考え方が大好きです。ソフトウェアは自由で透明であり、見知らぬ人同士が「それが正しいことだから」という理由で助け合い、一緒に作り上げられるという考えです。その思いに心を動かされ、どんなに小さくても何かをお返ししたいと思いました。

私にできるのは、次のことです。F-Droid の本拠地は GitLab にあり、GitHub では新しいリリースを公開しなくなりました。公式サイトや GitLab にアクセスできないとき——私のいる場所ではよくあることです——最新のクライアントを入手する手段がなくなってしまいます。ストア自体をインストールできなければ、その先にある何千もの FOSS アプリに出会うこともできません。それはおかしいと感じました。特に、私と同じような学生や好奇心旺盛な子ども、学び始めたばかりの人にとってはなおさらです。そこで、このリポジトリを作りました。F-Droid がビルドして署名した公式 Android クライアントの新しいリリースを、そのままミラーします。改変も再パッケージも一切しません。正面の入口を通れない人のための、もうひとつの入口だと思ってください。

## 各リリースに含まれるもの

公式クライアントの新しいリリースが出るたびに、**必ず2つの主要ファイル**をアップロードします。さらに、詳しく検証したい人のために、公式鍵も一緒に置いています。

- `F-Droid_<version>.apk` — 変更を加えていない公式クライアント
- `F-Droid_<version>.apk.sha256.txt` — 該当 APK の**ファイルハッシュ**を記載したプレーンテキストファイル
- `f-droid.org-signing-key.gpg` — リリースチェーンを詳しく検証するための公式 GPG 公開鍵（下記参照）

`.sha256.txt` は単なるテキストファイルです。スマートフォンで開けば、このビルドの SHA-256 が1行で表示されます。意図的に `.txt` のままにしています。拡張子をなくすような細工はせず、どの端末でも開けて、初めての人にも読めるようにするためです。

## `.sha256.txt` ファイルについて（ここは必ず読んでください）

**`.txt` 内のハッシュは APK ファイル自体のハッシュです。署名証明書のフィンガープリントではありません。この2つはまったく別のものです。**

- APK のビルドは毎回異なるため、**このファイルハッシュはバージョンごとに変わります。** 新しいバージョンなら新しいハッシュになるのが正常です。
- これはダウンロード中にファイルが破損しなかったことだけを証明します。**誰がパッケージに署名したかは証明しません。**
- 本当に F-Droid の公式パッケージか確認するには、証明書を別途検証してください（次のセクションを参照）。

ほとんどのコンピューターで使える簡単な確認方法：

```sh
sha256sum -c F-Droid_*.apk.sha256.txt
```

スマートフォンに `sha256sum` がない場合は、`.txt` を開いて中のハッシュとリリースページに表示された値を比べてください。一致すれば、ダウンロードしたファイルは完全です。

## 署名も検証してください（省略しないでください）

検証方法は3段階あります。普段のインストールなら最初の2つで十分です。3つ目は、念入りに確認したい人のための予備の鍵です。

| | ファイルハッシュ（`.txt`） | 証明書のフィンガープリント（**Android の要**） | GPG 公開鍵（リリースチェーンの高度な検証） |
|---|---|---|---|
| 何を証明するか | ダウンロードしたファイルが破損していないこと | パッケージが本当に F-Droid のものであること | 公式リリースチェーンが改ざんされていないこと |
| 変わるか | **バージョンごとに変わる** | **変わらない**（2037年まで有効） | **フィンガープリントは変わらない**（2037年まで有効。更新後も同じ鍵） |
| 確認方法 | `sha256sum -c` または目視 | `keytool -printcert -jarfile` | `gpg --verify`（`.asc` ファイルが必要） |
| 日常での優先度 | 便利 | ⭐ **最も重要 — インストールごとに確認** | 任意。コンピューターで実施 |

確認すべき**Android 証明書のフィンガープリント**は、**常に**次の値です。インストールや更新時に Android が確認する値です。

```
43238d512c1e5eb2d6569f4a3afbf5523418b82e0a3ed1552770abb9a9c9ccab
```

（F-Droid が公開している長期使用の署名証明書で、有効期限は2037年です。）

- **APK のハッシュが一致しない？** 問題ありません。リリースごとに異なります。
- **証明書が一致しない？** そこで中止してください。ファイル名が正しそうでも、ハッシュが「きれい」に見えても、**インストールしないでください**。
- Linux / macOS では、次のコマンドを実行してください。

  ```sh
  keytool -printcert -jarfile F-Droid_*.apk
  ```

  同じ証明書の値が表示されるはずです。Android は署名が一致しない今後の更新も拒否します。そのため、**最初のインストール**を正しく行えば、その後の更新も安全に続けられます。

### 上級者向け：GPG リリース署名（任意ですが、知っておくと便利です）

このリポジトリに含まれる `f-droid.org-signing-key.gpg` は公式公開鍵です。上記の **Android 署名証明書とは別の鍵**です。混同しないでください。

- **Android 証明書**（上の表の中央）：インストール時に Android が確認するものです。なりすましを防ぎます。2037年までは、フィンガープリントは常に `43238d…ccab` です。
- **GPG 公開鍵**（このセクション）：コンピューターで検証するときに使います。APK と同じ場所にある公式 `.asc` 署名ファイルを検証し、パッケージが F-Droid 自身のリリースチェーンから配布されたことを確認します。

**`.gpg` ファイルの使い方：**

1. 鍵を一度インポートします。

   ```sh
   gpg --import f-droid.org-signing-key.gpg
   ```

   公式主鍵のフィンガープリントは次のとおりです。インポート時に照合してください。

   ```
   37D2 C987 89D8 3119 4839  4E3E 41E7 044E 1DBA 2E89
   ```

   フィンガープリントが同じ = 更新されていても同じ鍵です。

2. リリース署名を検証します（APK と同じ場所にある公式 `.asc` ファイルが必要です）。

   ```sh
   gpg --verify F-Droid_<version>.apk.asc F-Droid_<version>.apk
   ```

   `Good signature from "F-Droid ..."` と表示されれば、リリースチェーンは正常です。

**⏳ 2037年の有効期限について：**

この GPG 鍵は **2037年**まで有効です。それ以降は、検証時に `key expired` と表示される場合があります。これは**改ざんではなく、通常の期限切れ**です。公式チームが鍵を更新し、フィンガープリントが変わらなければ同じ鍵です。

> スマートフォンで普段インストールする場合は、上記の **Android 証明書のフィンガープリント**と、一致する `.sha256.txt` があれば十分です。これだけでも非常に堅牢です。GPG は念のための備えです。鍵はここにあるので、必要になったときに使えます。

## これからも続けます

このリポジトリは一度だけアップロードして終わりではありません。最初のリリースの後に姿を消すつもりもありません。ネットワークが不安定でも、学校が忙しくても、できる限り続けます。いつも迅速に対応できるとは約束できませんが、続けていくことは約束できます。公式の新バージョンが出たら、APK と `.sha256.txt`、そして `.gpg` 鍵をここに置きます。同じファイル、同じルールです。
